# 상품·옵션 스키마 및 매핑 구현

작성: 2026-10-28, 갱신: 2026-10-29. **production 마이그레이션·네이버 상품/옵션 저장 완료 / 공급처 저장·매핑 미실행**. [초기 마이그레이션 결과](DB-MIGRATION-2026-10-29.md), [최신 상품 바인딩 결과](PRODUCT-BINDING.md).

후속 업데이트: 같은 날 사용자 요청으로 실제 네이버 상품 8개·옵션 16개를 저장했습니다. 공급처 상품/옵션 저장과 매핑 영속화는 여전히 미실행입니다. 최신 상태는 [상품 바인딩 결과](PRODUCT-BINDING.md)를 참고하세요.

## 테이블과 설계

| 테이블                | 역할                                                                              |
| --------------------- | --------------------------------------------------------------------------------- |
| StoreProduct          | 스토어별 네이버 원상품 번호, 제조사 품번 원본, 판매가, 네이버 상태, 미매핑 사유   |
| StoreProductOption    | 네이버 옵션 ID, 원본 그룹/값, 색상/사이즈, 추가 판매가, 재고 및 사용 여부         |
| SupplierProduct       | 공급처 전체 it_id, 상품명(미확인 시 null), 기본 공급가, 상태, 최초 기준 수집 여부 |
| SupplierProductOption | 옵션 원문, 공급가, 바코드 후보, 식별자 출처, 실제 제공된 중량, 활성 여부          |
| ProductMapping        | 스토어 상품과 공급처 상품 연결, 첫 글자+마지막 5자리 매핑 키                      |
| OptionMapping         | 스토어 옵션과 공급처 옵션 일대일 연결, 적용 규칙과 확인 상태                      |
| ProductChangeLog      | 상품/옵션 변경 전후 JSON, 변경 유형, 동기화별 이벤트 중복 방지 키                 |
| SyncHistory           | 요청 멱등 키, 실행 출처, 처리/변경 건수, 성공·부분성공·실패와 안전한 오류 코드    |

가격은 `Decimal(18,2)`, 중량은 `Decimal(12,4)`로 저장합니다. 프론트엔드 및 매핑 코드에서는 가격을 문자열로 전달하며 부동소수점으로 계산하지 않습니다. `isSample`은 사용하지 않습니다.

각 옵션의 소속 상품을 복합 외래 키로 확인하여 다른 상품의 옵션이 연결되는 일을 방지합니다. 삭제는 모두 RESTRICT입니다. 공급처 옵션 삭제는 데이터 삭제 대신 `active=false`로 표현하도록 설계했습니다. 생성·수정일과 조회 인덱스를 포함합니다.

`StoreProductOption.groupValues` 원본 형식은 `[{"name":"size","value":"11"}]`입니다. 공급가와 네이버 옵션 추가 판매가는 별개입니다.

## 구현한 매핑 규칙

- 상품: B/R/N+숫자 9자리 품번에서 첫 글자와 마지막 5자리를 모두 비교합니다. 후보 중복 제거 후 정확히 1건만 매칭합니다.
- 검증된 정상 검색 0건만 SOLD_OUT, 인증·네트워크·파싱·미검증 검색은 FAILED입니다. E 등 지원 외 분류는 UNSUPPORTED입니다.
- 옵션: 사이즈 전용 그룹은 Silver의 같은 사이즈, 색상+사이즈 그룹은 둘 다 비교합니다. 옵션이 없는 상품은 Silver로 추정하지 않습니다.
- 후보 없음, 중복, 불명확한 그룹, 잘못된 가격·식별자는 확인 필요입니다. 공급처 옵션 하나를 스토어 옵션 여러 개에 임의 연결하지 않습니다.
- 가격은 `itop_pay[]` 실제 값을 사용하며 표시 추가금을 다시 더하지 않습니다.
- 매핑 함수와 미리보기 API는 DB에 쓰지 않습니다. 동일 입력은 동일 계획을 반환합니다.

`GET /api/products/:id/options/preview`는 저장된 상품/옵션으로 계획만 반환합니다. 마이그레이션 후 실제 빈 상품 목록 조회와 없는 상품의 미리보기 404는 확인했습니다. 데이터가 있는 옵션의 실제 DB 미리보기는 미검증입니다. 현재 관리자 전체 인증이 완성되지 않았으므로 API를 공개 배포하지 마세요.

기존 샘플 동기화는 중단했습니다. `/api/suppliers/sync`는 인증 없으면 403, 올바른 서버 토큰이 있더라도 현재는 501입니다. 이전 개발 허용 플래그로 인증을 우회할 수 없습니다.

## 실제 자료로 확인한 범위

`pnpm mapping:preview`는 Git 제외된 로컬 진단 파일만 읽고 네트워크/DB 쓰기를 하지 않습니다.

- 스토어 R260115255 ↔ 공급처 R230315255: 공급처 옵션 15개 중 Silver 9/11/13/15/17의 5개 매핑 성공, 공급가 각 11000원.
- Gold/RoseGold 10개는 스토어의 사이즈 전용 옵션에 연결하지 않습니다.
- 해당 자료는 상세 페이지 증거이므로 정상 검색 성공으로 승격하지 않습니다. 나머지 상품은 자료 부족 상태로 유지합니다.
- 바코드는 BARCODE_CANDIDATE입니다. 공급처 옵션 ID의 영속성은 미검증입니다.
- 자동 품절 판정은 활성화하지 않았습니다. 로그인 만료와 정상 0건을 구분할 HTML 증거가 더 필요합니다.

## 마이그레이션 계획 및 적용 기록

아래 계획은 2026-10-29 사용자 승인 후 적용했습니다. 상세 결과와 P3015 해결 기록은 적용 보고서를 참고하세요. 상품 데이터는 삽입하지 않았습니다.

적용 후보: `packages/database/prisma/migrations/20261028090000_store_supplier_options/migration.sql`.

1. 실행 직전 현재 DB와 테이블·마이그레이션 이력을 다시 읽기 전용 확인합니다.
2. 승인 후 기존 production 브랜치에 테이블 8개, enum 7개, 인덱스와 외래 키를 생성합니다.
   Prisma Migrate는 이와 별도로 `_prisma_migrations` 관리 테이블을 생성합니다.
3. 테이블 삭제, 데이터 초기화, 샘플 삽입, 새 브랜치/리소스 생성은 없습니다. SQL은 BEGIN/COMMIT으로 묶었습니다.
4. 새 유료 리소스는 없지만 기존 Neon 사용량 과금은 계정 요금제에 따릅니다. 무조건 무료라고 보장하지 않습니다.
5. 적용 후 상품 API와 옵션 미리보기의 실제 DB 조회를 검증합니다. 실제 데이터 입력/지속 동기화는 별도 수집·식별자 검증을 마친 뒤 진행합니다.

이전 샘플 스키마·미적용 SQL·샘플 동기화 코드는 `docs/archive/`로 이동 보존했습니다. Git diff의 삭제 표시는 보관 위치 변경이며 DB 삭제가 아닙니다. 기존 샘플 seed는 DB 변경 없이 오류 종료합니다.

## 명령 및 남은 작업

Windows PowerShell/macOS 터미널 공통: `pnpm test:mapping`, `pnpm mapping:preview`, `pnpm test`, `pnpm build`.

`pnpm security:check`는 Git 추적 및 비제외 파일에서 현재 로컬 환경파일의 비밀값과 인증정보가 포함된 DB URL을 검사합니다. 값 자체는 출력하지 않으며 Git 과거 이력·알 수 없는 비밀값을 모두 탐지한다고 보장하지 않습니다.

검증 결과(2026-10-28): Prisma 스키마 검증 및 클라이언트 생성 성공, `pnpm build` 성공, `pnpm test` 32개 통과(이전 Decimal/샘플 유틸리티 5개 + 네이버/보안/매핑 API 합성 테스트 10개 + 순수 매핑 12개 + 진단 확장 5개), lint/포맷 검사 통과, 고정 의존성 설치 성공. `/health`, `/health/db` 실제 Fastify 주입 요청은 모두 200이며 DB SELECT 1 성공, 테이블 조회 결과는 빈 배열입니다. Vite 번들 크기 경고는 남아 있습니다. 합성 테스트 통과를 실제 DB 옵션 저장 성공으로 해석하면 안 됩니다.

이번 작업에서 `pnpm dev`를 새로 실행하지는 않았습니다. 기존 개발 프로세스는 임의 종료하지 않고 유지했습니다. 변경 UI의 브라우저 동작과 마이그레이션 후 상품 API 조회는 미검증입니다. `pnpm security:check`는 현재 Git 대상 파일 77개에서 검사 패턴과 로컬 환경파일 비밀값을 발견하지 않았습니다.

추가 설치 패키지는 없습니다. 새 PC에서는 루트 README의 Node/pnpm 및 `pnpm install --frozen-lockfile` 절차를 따르세요. 미리보기에는 기존 PC의 비밀정보가 아닌 상품 진단 자료가 별도로 필요하며 Git으로 동기화하지 않습니다.

Windows에서 API가 Prisma 엔진 DLL을 사용 중이면 `prisma generate`가 EPERM으로 실패할 수 있습니다. `packages/database/scripts/generate.mjs`는 생성된 스키마·클라이언트/CLI 버전이 정확히 같을 때만 재생성을 생략합니다. 실제 스키마가 바뀌어 재생성이 필요한 경우에는 실행 중인 본인 개발 서버를 종료한 뒤 다시 실행하세요. 서버를 자동 종료하지 않습니다.

남은 검증: production 마이그레이션, 실제 옵션 연결 저장, 최초 기준 수집/변경 이력의 DB 트랜잭션, 반복 수집 시 무변경 UPDATE 방지, 옵션 ID 영속성, 정상 검색/인증 실패 구별, 실제 상품명·중량 수집, 확장 프로그램 관리자 인증, 관리자 옵션 비교 UI.
