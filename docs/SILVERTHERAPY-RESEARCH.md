# 실버테라피 실제 데이터 구조 검증

검증일: 2026-10-28. DB 스키마 확정 및 마이그레이션 적용 전 단계입니다. 전체 최신 현황은 [프로젝트 현황 문서](LUMETTE-PROJECT-STATUS.md)를 참고합니다.

## 실제 확인 자료

사용자가 로그인한 Chrome에서 진단 확장 프로그램으로 직접 전송한 결과를 사용했습니다. 비로그인 HTTP 응답이나 합성 테스트를 실제 상품 데이터로 간주하지 않았습니다. 원본 진단 JSON은 Git 제외 폴더 `.diagnostics/silvertherapy`에만 있습니다.

- 검색: `GET /silver/product_list.php?keyword=57427`
- 검색 진단에서 수집한 상세 링크의 고유 상품 코드: `R221057427` 1개
- 초기 입력 코드 `R221057427`과 첫 글자 `R`, 끝 5자리 `57427`이 일치. 사용자가 이후 확인한 바에 따르면 이 코드는 실제 스토어 미등록 상품이며 거래처 구조 검증용으로만 사용함
- 상세: `/silver/product_detail_serve.php?it_id=R221057427`
- 이 한 사례에서는 끝 5자리 검색이 상품을 반환했습니다. 전체 카테고리와 모든 상품에서의 동작을 보장하지는 않습니다.
- 정상 0건 결과 및 인증 만료의 구별 표식은 아직 미검증입니다. HTTP 200이나 링크 부재만으로 품절 처리하지 않습니다.

추가로 사용자가 로그인한 상태에서 보낸 `keyword=59999` 진단은 상품 링크 0개, 상품 필드 0개, 검색 폼 2개였습니다. 이 자료는 빈 검색 결과 사례로 확보했습니다. 진단의 SKU 입력란에는 R221057427이 남아 있지만 실제 검색어는 57427이 아닌 59999이므로 해당 상품의 품절 증거로 사용하지 않습니다. 현재 진단은 정상 검색/인증 만료를 식별할 표식이 없어 이 사례도 자동 품절 판정에 사용하지 않습니다. 로그인 만료 자료는 추후 비교 예정입니다.

## 상세에서 실제 수집한 필드

| 필드           | 개수 | 관측                                                                                                 |
| -------------- | ---- | ---------------------------------------------------------------------------------------------------- |
| it_id          | 1    | R221057427                                                                                           |
| it_pay         | 1    | 42000                                                                                                |
| itop_subject[] | 12   | Silver/Gold/Rose Gold × 11/13/15/17                                                                  |
| it_barcode[]   | 12   | 옵션별 서로 다른 바코드 후보                                                                         |
| itop_pay[]     | 12   | Silver 42000, Gold/Rose Gold 47000. 두 번째 상세 진단에서 각각 동일 옵션 DOM 컨테이너 안의 관계 확인 |
| itop_qty[]     | 12   | 수량 선택 상자, 현재 값 0. 재고나 품절 표시로 해석하지 않음                                          |
| itop_on[]      | 0    | 이번 진단 결과에는 없었음. 안정적인 옵션 ID로 사용할 근거 없음                                       |

11호의 반복 필드 관측값:

| 옵션명       | 바코드 후보 | itop_pay[] 후보 값 |
| ------------ | ----------- | ------------------ |
| Silver 11    | S58150031Z  | 42000              |
| Gold 11      | G58150031Z  | 47000              |
| Rose Gold 11 | P58150031Z  | 47000              |

첫 상세 진단은 옵션 행이 0개여서 배열 순서 이외의 DOM 연결 증거가 부족했습니다. 수집기 보완 후 받은 두 번째 상세 진단에서는 옵션 컨테이너 12개가 수집됐고, 각 컨테이너 안에 옵션명 1개·가격 1개 및 바코드가 함께 존재함을 확인했습니다. 옵션명 12개와 바코드 12개는 각각 중복이 없었습니다.

| 색상      | 실제 수집된 사이즈 | itop_pay[] | 화면 표시 추가금 |
| --------- | ------------------ | ---------- | ---------------- |
| Silver    | 11, 13, 15, 17     | 각 42000   | 별도 표시 없음   |
| Gold      | 11, 13, 15, 17     | 각 47000   | (+5,000)         |
| Rose Gold | 11, 13, 15, 17     | 각 47000   | (+5,000)         |

이 상품에서는 기본가 42000과 표시 추가금 5000을 합한 47000이 `itop_pay[]`에 이미 들어 있습니다. 따라서 옵션 금액에 표시 추가금을 다시 합산하면 안 됩니다. 부가세·결제 시 할인 등 상거래 조건은 이 진단으로 확인하지 않았습니다. 다른 상품까지 같은 가격 구조라고 일반화하지 않습니다.

두 상세 진단에서 상품 코드·기본가·옵션명·바코드·옵션 가격 필드 값의 차이는 없었습니다. 다만 장기간 유지되는 공급처 고유 ID임을 보장하지 않으므로 바코드는 아직 식별자 후보입니다.

사용자는 특정 테스트 옵션 하나로 수집 범위를 제한하지 않고 상품별 전체 옵션을 분석하도록 요청했습니다. 공급처 옵션 전체 수집과 현재 네이버 판매 옵션 연결은 구분합니다. 이후 실제 네이버 옵션 조회와 사용자 확인을 통해, 사이즈 옵션만 있는 상품은 Silver라는 공통 업무 규칙을 확정했습니다. 색상과 사이즈 옵션이 모두 있으면 두 값으로 연결하며, 옵션이 아예 없는 상품에는 이 기본색 규칙을 적용하지 않습니다.

## 실제 판매 상품의 연결 조건 확인 (추가 진단)

2026-10-28 17:20에 수신한 상세 진단의 거래처 코드는 `R230315255`입니다. 네이버에서 실제 조회한 상품 중 `R260115255`(원상품번호 12871392673, 데일리 물결 웨이브 레이어드링 실반지)와 분류 R 및 끝 5자리 15255가 일치했습니다.

- 이 자료는 상세 페이지입니다. 같은 검색어의 정상 검색 결과에서 후보가 정확히 하나인지까지 검증한 것은 아닙니다. 현재 스토어 목록에서 이 거래처 코드와 매핑 키가 일치하는 판매 상품은 하나입니다.
- 확장 프로그램의 SKU 입력란에는 거래처 코드 `R230315255`가 입력돼 있었습니다. 운영 구현은 해당 입력값을 판매 상품의 원본 품번으로 신뢰하지 않고, 네이버에서 확인한 `R260115255`를 기준으로 작업 대상을 지정해야 합니다.
- 거래처 기본가 11000, 옵션 15개. Silver × 9/11/13/15/17은 각각 11000, Gold 및 Rose Gold × 같은 사이즈는 각각 14000입니다. 옵션 컨테이너 안에 표시 추가금 (+3,000)과 itop_pay 14000이 함께 있어 이 사례도 추가금 포함 옵션 금액 구조임을 확인했습니다.
- 바코드는 15개가 모두 고유합니다. 이번 상품의 장기 안정성 및 다른 상품과의 전역 고유성은 아직 미검증입니다.
- 네이버 원상품에는 옵션 그룹 size 및 9/11/13/15/17의 5개 조합형 옵션만 존재합니다. 색상 그룹/값은 응답에서 없었습니다. 이후 사용자가 이 상품은 Silver만 판매 중이고, 다른 상품도 사이즈 옵션만 있으면 Silver라는 공통 규칙을 확인했습니다. 따라서 이 상품의 네이버 5개 옵션은 거래처 Silver의 같은 사이즈에 연결하는 규칙으로 설계합니다. 거래처 Gold/Rose Gold 10개는 현재 판매 옵션에 연결하지 않습니다. 이 매핑은 아직 운영 DB에 적용하지 않았으며 네이버 상품도 수정하지 않습니다.
- 상세 페이지의 상품 링크에는 현재 상품 외에 관련 상품 코드도 포함돼 있었습니다. 상세 페이지의 모든 링크를 검색 후보로 간주하면 안 됩니다. 검색 응답 정상성·검색 영역을 검증한 뒤 후보를 추출해야 합니다.
- 상품과 옵션은 분석만 했으며 DB 저장 및 네이버 상품 수정은 실행하지 않았습니다.

## 남은 검증

1. 상품명·중량 위치는 추가 확인합니다. 필드 미수집을 사이트에 해당 정보가 없다는 뜻으로 해석하지 않습니다.
2. 정상 검색 0건, 로그인 만료/인증 실패 응답을 구별할 수 있는 표식을 검증한 뒤 품절/판매 재개 로직을 확정합니다. 빈 상세도 이 표식 검증 전에는 품절로 판정하지 않습니다.
3. 네이버 실제 인증과 상품 8개·상세 8개 조회는 2026-10-28에 성공했습니다. 품번 위치는 `originProduct.detailAttribute.manufactureDefineNo`이며 테스트 거래처 코드 R221057427은 조회된 판매 상품에는 없었습니다. 실제 판매 품번과 모든 판매 옵션의 매핑 기준은 이 응답을 바탕으로 정해야 합니다. [네이버 확인 결과](NAVER-COMMERCE-SETUP.md)를 참고합니다.
4. 다른 가격 구조(중량 등)를 가진 실제 판매 대상 상품이 있으면 해당 상품만 소량 검증합니다. 거래처 전체 상품을 수집하지 않습니다.

현재 설계 결론: 기본 가격을 모든 옵션에 복사하는 처리는 금지하고, itop_on[]이나 옵션 순번을 확정된 영구 식별자로 사용하지 않습니다. 이전 샘플 모델·미적용 SQL은 실연동용 최종 스키마가 아닙니다.
